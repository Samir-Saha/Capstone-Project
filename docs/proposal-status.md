# Proposal vs. repo

What the September 28, 2026 proposal promised, and where the code stands as of commit `296e647` (November 6, 2026).

Labels: **Built** works in the repo today. **Needs config** is written but only runs once a key or service is set up. **Partial** exists but is simpler than the proposal described. **Not started** has no code yet.

## Boss fights (exam practice)

| Proposal | Status | Notes |
| --- | --- | --- |
| Upload PDFs, slides, notes | Built | PDF, .docx, .pptx, .txt/.md and pasted notes, several files into one course (`ingest/`, `main.py` upload route) |
| AI generates practice questions from your material | Needs config | Needs `LLM_API_KEY`. Without a key, study mode builds questions from your notes |
| Correct answers hurt the boss, boss HP = readiness | Built | HP = 100 × (1 − average mastery) |
| Boss attacks your weakest areas | Built | Bayesian Knowledge Tracing per topic, plus forgetting (`tutor/knowledge_tracing.py`) |
| Math answers checked with SymPy | Built | Every answer key computed twice (SymPy and mpmath); show-your-work checks each line |
| Concept (non-math) questions | Needs config | Generated by the LLM and checked against your notes. A comment at the top of `generation.py` still calls them future work and is out of date |

## Gauntlet (mock interviews)

| Proposal | Status | Notes |
| --- | --- | --- |
| Starts from your resume | Built | PDF or pasted text |
| Resume split into claims | Partial | Uses simple rules (bullets, numbers), not AI |
| Interviewer drills into specific claims | Partial | Follow-ups come from fixed rules (for example, no number in the answer means a follow-up asks for one), not an AI interviewer |
| Speak out loud, spoken replies | Partial | Uses the browser's built-in speech recognition and speech synthesis (Chrome and Edge only), not paid speech-to-text or text-to-speech APIs. Not tested automatically |
| STAR grading for behavioral answers | Partial | Always checks which STAR parts have a recognizable phrase. Full AI STAR scores need `LLM_API_KEY` |
| Technical rounds use the code runner | Built | Same runner as the Arena |
| Filler words, pace, pauses | Built | Pace and pauses from microphone audio levels; filler counts run low because browser speech recognition drops "um" |

## Biggest gaps, in order

1. Set an LLM key and test question generation and AI STAR scoring end to end. Two of the six components depend on it.
2. Supabase login and per-user data. The proposal's "one profile" depends on it.
3. A report button on generated questions (promised in the proposal, small to build).
4. Judge0, configured and tested, before anyone else runs code on a hosted version.
5. Exam-date scheduling, or drop it from the background-jobs claim.
6. The three human studies (50-problem review, STAR agreement, 10-student trial).
